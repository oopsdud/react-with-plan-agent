## 0. 调研综述：业界怎么做

### 0.1 意图识别

| 方案 | 代表 | 优势 | 局限 | 我们的选择 |
|------|------|------|------|-----------|
| **LLM Function Calling** | OpenAI / DeepSeek | 结构化输出，可提取实体 | 每次调用 ~800ms，有成本 | 用于兜底 |
| **Embedding 语义路由** | [vLLM Semantic Router](https://blog.vllm.com.cn/2025/09/11/semantic-router.html) | 约 5ms 延迟，零 Token 消耗 | 需预定义意图描述 | **主通道** |
| **微调小模型** | [C-LARA / Symbol Tuning](https://ar5iv.labs.arxiv.org/html/2411.12307) | 极高吞吐（V100 单卡），准确率 65%+ | 需标注数据，训练成本 | 未来迭代 |
| **关键词规则** | 传统 NLP | 零延迟，确定性 | 覆盖率低，维护成本高 | 作为 fast-path |

**vLLM Semantic Router 架构参考**：
```
用户查询 → ModernBERT 分类器（~5ms）→ 路由决策
           ↓ 不确定时
         LLM Function Calling（~800ms）→ 最终决策
```
效果：准确率提升约 10%，延迟降低约 50%，Token 消耗减少约 50%。

### 0.2 任务规划模式

| 模式 | 核心思想 | 适用场景 |
|------|---------|---------|
| **Plan-and-Execute** | 先完整规划，再逐步执行 | 长周期任务，执行不偏离大方向 |
| **ReWOO** | 计划含占位符，工具并行执行后代入 | 可并行工作负载，效率数倍于串行 |
| **ReAct** | 边推理边行动，逐步决策 | 开放型任务，透明度高 |
| **Tree-of-Thoughts** | 多方案树搜索 + 剪枝 | 复杂推理，成本高 10-50 倍 |
| **Reflexion** | 失败后生成自然语言反思，存入记忆 | 有明确成功/失败信号的任务 |

**我们的混合策略**：
```
简单高频任务 → Plan-and-Execute + 模板（零 LLM 消耗）
复杂低频任务 → Plan-and-Execute + LLM 动态规划
可并行步骤   → ReWOO 占位符 + 并行执行
步骤失败时   → Reflexion 反思 → 修复重试
```

### 0.3 反思与自我修正

[业界四级反思模型](https://developer.cloud.tencent.cn/techpedia/2673/21332)：

| 级别 | 机制 | 效果 |
|------|------|------|
| L1 内在反思 | 提示词"请检查你的答案" | 有限，共享盲区 |
| L2 基于执行的反思 | 外部环境反馈（如单元测试） | 客观可靠 |
| L3 过程奖励模型 | 对推理链每步打分 | 早期检测偏差 |
| L4 多 Agent 辩论 | 多角色相互审查 | 高价值场景 |

**我们的实现**：L2（工具执行结果反馈）为主，L1（LLM 自检）为辅，关键任务引入 L4（审批即人工审查）。

### 0.4 记忆类型

[四类记忆模型](https://developer.cloud.tencent.cn/techpedia/2673/21328)：

| 类型 | 存储内容 | 我们的映射 |
|------|---------|-----------|
| **工作记忆** | 当前上下文窗口 | AgentState.context + 压缩摘要 |
| **情景记忆** | 具体时间戳事件 | ChromaDB `semantic_memory` |
| **语义记忆** | 抽象事实和偏好 | MySQL `memory_facts` |
| **程序记忆** | 工作流程和模式 | 计划模板 + 提示词版本化 |

## 1. 意图识别模块（Intent Router）

### 1.1 设计：四级路由管线

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│ Level 1: 语义路由（Embedding 相似度，~5ms）              │
│   预定义意图描述集合：                                     │
│     "读取事件并发送通知" → notify_event                   │
│     "生成生日祝福并发送" → greeting                        │
│     "将文档导入知识库" → ingest_document                   │
│     "搜索知识回答问题" → knowledge_qa                      │
│     "巡检IT资源池" → it_inspection                         │
│     "通用对话" → general                                  │
│                                                          │
│   计算：cosine_sim(embed(输入), embed(每个意图描述))       │
│   取 top-1，若相似度 > 0.85 → 直接命中                     │
└────────────────────┬────────────────────────────────────┘
                     │ 未命中或相似度低
                     ▼
┌─────────────────────────────────────────────────────────┐
│ Level 2: 多标签分类（支持任务组合）                         │
│   输入可能同时涉及多个意图：                                │
│     "导入这个文档然后通知大家"                              │
│     → [ingest_document: 0.9, notify_event: 0.7]           │
│   输出：top-2 意图 + 置信度                                │
│   若 top-1 与 top-2 差距 < 0.15 → 标记为组合任务           │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│ Level 3: 上下文感知（多轮对话）                             │
│   读取最近 3 轮对话历史：                                    │
│     用户: "帮我查一下年假政策"          → knowledge_qa      │
│     用户: "顺便通知一下同组的同事"                           │
│     → 结合上下文，意图为 [knowledge_qa, notify_event]     │
│   实现：将历史摘要 + 当前输入一起 embedding，               │
│         与意图描述做相似度匹配                               │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│ Level 4: LLM Function Calling（兜底，~800ms）              │
│   当以上三级置信度均 < 0.6 时触发                           │
│   使用 LLM 结构化输出：                                    │
│   {                                                      │
│     "route": "notify_event",                             │
│     "confidence": 0.88,                                  │
│     "virtual_user_ids": ["uuid-1"],                      │
│     "reasoning": "用户提到'通知'和具体人名"                │
│   }                                                      │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
              输出: RouteDecision
```

### 1.2 伪代码

```pseudocode
CLASS RouteDecision:
    route: str                    # 主意图
    secondary_routes: list[str]   # 次要意图（组合任务）
    confidence: float             # 总体置信度 [0, 1]
    virtual_user_ids: list[str]   # 涉及的用户
    reasoning: str                # 决策理由（可审计）

CLASS IntentRouter:
    # 预定义意图描述（用于 embedding 匹配）
    INTENT_DESCRIPTIONS = {
        "notify_event":    "读取用户事件并发送通知提醒",
        "greeting":        "生成个性化祝福或问候内容",
        "ingest_document": "将文档解析入库建立知识索引",
        "knowledge_qa":    "搜索已有知识库回答问题",
        "it_inspection":   "巡检IT资源池检查系统状态",
        "general":         "通用对话或无法归类的请求"
    }

    FUNCTION route(task, session_history) -> RouteDecision:
        # ---- Level 1: 语义路由 ----
        query_embedding = embedding_model.encode(task)
        similarities = {}
        FOR EACH (route_name, description) IN INTENT_DESCRIPTIONS:
            desc_embedding = embedding_model.encode(description)  # 可预计算缓存
            similarities[route_name] = cosine_similarity(query_embedding, desc_embedding)

        top_route, top_score = argmax(similarities)
        IF top_score > 0.85:
            RETURN RouteDecision(route=top_route, confidence=top_score, ...)

        # ---- Level 2: 多标签 ----
        sorted_routes = sort_by_score(similarities)
        primary = sorted_routes[0]
        secondary = sorted_routes[1] IF sorted_routes[1].score > 0.6 ELSE None
        is_multi = primary.score - (secondary.score IF secondary ELSE 0) < 0.15

        # ---- Level 3: 上下文感知 ----
        IF session_history EXISTS:
            context_text = session_history.last_n_turns(3).join(" ")
            combined_embedding = embedding_model.encode(context_text + " " + task)
            # 重新计算相似度，倾向保持与上文一致的意图
            ...

        # ---- Level 4: LLM 兜底 ----
        IF primary.score < 0.6:
            llm_result = llm.chat(
                prompt=ROUTER_PROMPT.format(task=task, history=session_history),
                response_format=RouteDecision       # 强制 JSON Schema 输出
            )
            RETURN llm_result

        RETURN RouteDecision(
            route=primary.name,
            secondary_routes=[secondary.name] IF is_multi ELSE [],
            confidence=primary.score,
            virtual_user_ids=extract_user_mentions(task),
            reasoning=f"语义相似度 {primary.score:.2f}"
        )
```

### 1.3 升级点

| 升级 | 说明 |
|------|------|
| **语义路由前置** | 从"每次 LLM 调用"改为"5ms embedding 匹配"，成本降低 90%+ |
| **多标签分类** | 支持组合任务（如"入库 + 通知"），V1 只能单选 |
| **上下文感知** | 多轮对话中意图自动继承，V1 每轮独立判断 |
| **置信度透明** | 每个决策附带 reasoning，可审计、可回放 |
| **可插拔** | 未来可将 embedding 分类器替换为微调小模型（C-LARA 方案） |

## 2. 规划器（Planner）

### 2.1 设计：分层规划 + ReWOO 占位符

```
┌──────────────────────────────────────────────────────────┐
│  输入: RouteDecision + Memory + Tool Catalog              │
│                                                          │
│  第一步：确定规划模式                                       │
│    IF route 有预定义模板 AND 任务参数简单:                  │
│      → 模板模式（零 LLM 消耗）                             │
│    ELSE:                                                  │
│      → LLM 动态规划                                       │
│                                                          │
│  第二步：生成计划                                           │
│    模板模式: 直接返回预定义 PlanStep[]                     │
│    LLM 模式:                                               │
│      - 注入 Memory（用户画像 + 相似任务）                   │
│      - 注入 Tool Catalog（带参数 Schema）                  │
│      - LLM 生成 PlanStep[]                                │
│      - JSON Schema 校验                                   │
│      - 工具存在性校验（剔除幻觉工具）                       │
│                                                          │
│  第三步：ReWOO 占位符替换                                   │
│    步骤间有数据依赖时，用占位符引用前序结果：                 │
│      Step 3 参数: {email: "{{step_1.result.user.email}}"} │
│    执行时由 Executor 负责渲染                              │
│                                                          │
│  第四步：并行性标注                                         │
│    分析步骤依赖 DAG，标记可并行组：                         │
│      Step 2 和 Step 3 无依赖 → 标记为并行                  │
│      Executor 用 asyncio.gather 同时执行                   │
└──────────────────────────────────────────────────────────┘
```

### 2.2 伪代码

```pseudocode
CLASS PlanStep:
    id: int
    action: str                  # 工具名
    description: str             # 人可读描述
    arguments: dict              # 参数（可含 {{placeholder}}）
    depends_on: list[int]        # 依赖的步骤 ID（DAG）
    parallel_group: int | None   # 并行组编号
    needs_approval: bool         # 是否需人工审批
    max_retries: int = 3

CLASS Planner:
    PLAN_TEMPLATES = {
        "notify_event": [
            PlanStep(1, "query_events",       args={date: "today"}),
            PlanStep(2, "query_memory_facts", args={keys: ["preferred_tone", "preferred_channel"]}),
            PlanStep(3, "send_notification",  args={channel: "{{step_2.result.preferred_channel}}"},
                     needs_approval=True),
            PlanStep(4, "write_fact",         args={key: "last_notify_sent"}),
            PlanStep(5, "respond",            args={format: "notify_report"}),
        ],
        "greeting": [...],
        "ingest_document": [...],
    }

    FUNCTION plan(task, route_decision, memory, tools) -> list[PlanStep]:
        # ---- 模式选择 ----
        IF route_decision.route IN PLAN_TEMPLATES AND is_simple_task(task):
            RETURN PLAN_TEMPLATES[route_decision.route].copy()

        # ---- LLM 动态规划 ----
        memory_context = memory.recall_facts(
            user_ids=route_decision.virtual_user_ids
        )
        similar_tasks = memory.semantic_search(task, top_k=3)

        raw_plan = llm.chat(
            prompt=PLANNER_PROMPT.format(
                task=task,
                route=route_decision.route,
                memory=memory_context,
                similar_tasks=similar_tasks,
                tools=tools.get_descriptions()
            ),
            response_format=list[PlanStep]    # 强制结构化输出
        )

        # ---- 校验与清洗 ----
        validated = []
        FOR EACH step IN raw_plan:
            IF NOT tools.exists(step.action):         CONTINUE    # 剔除幻觉
            IF NOT tools.validate_args(step.action, step.arguments): CONTINUE
            step.id = len(validated) + 1
            validated.append(step)

        # ---- 依赖分析 ----
        FOR EACH step IN validated:
            step.depends_on = extract_dependencies(step.arguments)  # 解析 {{step_N.xxx}}
        parallel_groups = build_dag_and_group(validated)

        RETURN validated
```

### 2.3 升级点

| 升级 | 说明 |
|------|------|
| **ReWOO 占位符** | 步骤间数据引用显式化，支持并行执行后统一代入 |
| **DAG 依赖分析** | 自动识别可并行步骤，执行效率数倍于串行 |
| **模板 + 动态双模式** | 高频任务零 Token，低频任务灵活生成 |
| **相似任务注入** | 从历史记忆中检索相似计划，提高规划质量 |

## 3. 审批门（Approval Gate）

### 3.1 设计

```
┌──────────────────────────────────────────────────────────┐
│  风险判定规则（任一命中即需审批）:                           │
│    1. 计划包含 HIGH_RISK_TOOLS 中的工具                    │
│       （send_email / send_wechat / send_lzmx / batch_import）│
│    2. 影响用户数量 > 5                                      │
│    3. 涉及敏感数据修改（delete / update 类工具）             │
│    4. 当前时段为夜间（22:00-08:00）且非定时任务              │
│                                                          │
│  审批流程:                                                   │
│    生成 ApprovalTicket → 推送前端审批面板                   │
│    → LangGraph Interrupt（挂起，保存 checkpoint）          │
│    → 等待人工决议（超时 30min 自动降级）                     │
│    → 人工提交后 Resume，应用决议                             │
│                                                          │
│  决议类型:                                                   │
│    approve_all  : 全量通过，继续执行                        │
│    edit_steps   : 修改部分步骤后通过（提供 edited_steps）    │
│    reject       : 拒绝执行，生成拒绝报告                    │
└──────────────────────────────────────────────────────────┘
```

### 3.2 伪代码

```pseudocode
CLASS ApprovalTicket:
    ticket_id: str
    task_id: str
    original_plan: list[PlanStep]
    created_at: datetime
    expires_at: datetime           # created_at + 30min
    status: "pending" | "approved" | "edited" | "rejected" | "expired"
    resolution: ApprovalResolution | None

CLASS ApprovalGate:
    HIGH_RISK_TOOLS = {"send_email", "send_wechat_work",
                       "send_lzmx_message", "batch_import", "delete_resource"}

    FUNCTION check(state) -> RouteDecision:
        plan = state.plan
        risk_flags = {
            "has_high_risk_tool": ANY(step.action IN HIGH_RISK_TOOLS FOR step IN plan),
            "affects_many_users": len(state.target_user_ids) > 5,
            "is_night_time":      is_night_hours() AND NOT state.is_scheduled_task,
        }

        IF NOT ANY(risk_flags.values()):
            RETURN {plan_approved: True}          # 无需审批，直接通过

        # 生成审批单
        ticket = ApprovalTicket(
            ticket_id=uuid(),
            task_id=state.trace_id,
            original_plan=plan,
            expires_at=now() + 30min
        )
        approval_store.save(ticket)
        notification_gateway.send_to_admin_panel(ticket)   # 推送审批面板

        RETURN {
            plan_approved: False,
            approval_ticket: ticket,
            needs_human: True,
            # LangGraph Interrupt 触发条件
        }

    FUNCTION apply_resolution(state, resolution) -> dict:
        ticket = state.approval_ticket
        SWITCH resolution.type:
            CASE "approve_all":
                RETURN {plan_approved: True, needs_human: False}
            CASE "edit_steps":
                RETURN {plan: resolution.edited_steps,
                        plan_approved: True, needs_human: False}
            CASE "reject":
                RETURN {plan_approved: False, needs_human: False,
                        failure_reason: "人工拒绝: " + resolution.reason}
```

### 3.3 升级点

| 升级 | 说明 |
|------|------|
| **多维度风险判定** | 不只工具风险，还考虑时段、影响范围 |
| **审批超时降级** | 30 分钟未审批自动降级为低信任模式或取消 |
| **编辑后通过** | 人工可修改具体步骤参数，而非简单的"全通过/全拒绝" |

## 4. 执行器（Executor）

### 4.1 设计：DAG 并行 + 断点恢复

```
┌──────────────────────────────────────────────────────────┐
│  输入: PlanStep[]（含依赖 DAG + 并行组标注）                │
│                                                          │
│  执行策略:                                                   │
│    FOR EACH parallel_group IN plan:                       │
│      组内步骤 → asyncio.gather 并行执行                     │
│      组间     → 串行等待前序组完成                          │
│                                                          │
│  单步执行流程:                                               │
│    1. 参数渲染：替换 {{step_N.result.xxx}} 占位符           │
│    2. 工具查找：tool_registry.get(step.action)             │
│    3. 超时控制：asyncio.wait_for(tool.run(), timeout)     │
│    4. 结果处理：截断至 4KB → 写入 context → 更新 PlanStep   │
│    5. 失败处理：标记 failed，写入 error，等待 Replanner     │
│                                                          │
│  断点恢复:                                                   │
│    每个步骤完成后，LangGraph Checkpointer 自动保存           │
│    中断恢复时，从最后一个未完成步骤继续                      │
│    已成功步骤不重复执行（幂等保证）                           │
└──────────────────────────────────────────────────────────┘
```

### 4.2 伪代码

```pseudocode
CLASS Executor:
    FUNCTION execute(state) -> dict:
        plan = state.plan
        context = state.context
        current_idx = state.current_step_idx

        WHILE current_idx < len(plan):
            step = plan[current_idx]

            # ---- 参数渲染 ----
            rendered_args = render_placeholders(step.arguments, context)
            # render_placeholders: 将 "{{step_2.result.email}}" 替换为实际值

            # ---- 工具执行 ----
            tool = tool_registry.get(step.action)
            try:
                result = await asyncio.wait_for(
                    tool.run(rendered_args, tool_context=state),
                    timeout=tool.timeout_seconds
                )
                step.status = "succeeded"
                step.result = truncate(result.data, max_bytes=4096)
                context[f"step_{step.id}_result"] = step.result

            EXCEPT asyncio.TimeoutError:
                step.status = "failed"
                step.error = f"超时 ({tool.timeout_seconds}s)"
                step.retry_count += 1

            EXCEPT ToolError AS e:
                step.status = "failed"
                step.error = str(e)
                step.retry_count += 1

            # ---- 并行组判断 ----
            IF step.parallel_group IS NOT NULL:
                # 同组步骤同时启动
                group_steps = get_same_group_steps(plan, step.parallel_group)
                results = await asyncio.gather(
                    [execute_single(s, context) FOR s IN group_steps],
                    return_exceptions=True
                )
                # 处理组内结果
                ...
                current_idx += len(group_steps)
            ELSE:
                current_idx += 1

            # ---- Checkpoint 保存（LangGraph 自动）----
            # 无需手动调用，LangGraph 在每个节点后自动保存

        RETURN {
            plan: plan,
            context: context,
            current_step_idx: current_idx
        }
```

### 4.3 升级点

| 升级 | 说明 |
|------|------|
| **DAG 并行执行** | 无依赖步骤同时执行，总耗时降低 50%+ |
| **自动断点恢复** | LangGraph Checkpointer 每步自动保存，中断后精确恢复 |
| **结果截断** | 中间结果限制 4KB，防止超长文本污染下游 LLM 上下文 |
| **超时保护** | 每步独立超时，单步卡死不影响整体 |

## 5. 反思器（Replanner）

### 5.1 设计：Reflexion 模式

```
┌──────────────────────────────────────────────────────────┐
│  Reflexion 核心思想：                                         │
│    失败后不只重试，而是生成自然语言反思，                      │
│    将反思存入记忆，下次遇到类似情况时参考                      │
│                                                          │
│  三级反思策略：                                               │
│                                                          │
│  Level 1: 步骤级反思（单步失败时）                            │
│    分析：错误类型 → 修复策略                                  │
│    retry  : 参数微调后重试（最多3次）                         │
│    skip   : 跳过此步，继续后续                                │
│    replan : 整体重新规划                                    │
│    abort  : 终止任务，报告失败                                │
│                                                          │
│  Level 2: 任务级反思（任务整体失败时）                         │
│    生成反思摘要：                                            │
│      "任务失败原因：MCP Server 连接超时                       │
│       建议：检查 mcp-server:31958 健康状态                    │
│       影响：IT巡检中断，磁盘告警未发送"                       │
│    存入 semantic_memory（供未来相似任务参考）                  │
│                                                          │
│  Level 3: 全局策略反思（多次同类失败时）                       │
│    统计：最近 7 天同工具失败次数 > 5 次                       │
│    动作：自动降低该工具优先级 / 创建运维告警                   │
└──────────────────────────────────────────────────────────┘
```

### 5.2 伪代码

```pseudocode
CLASS Replanner:
    MAX_STEP_RETRIES = 3
    MAX_REPLAN_COUNT = 3

    FUNCTION replan(state) -> RouteDecision:
        plan = state.plan
        failed_steps = [s FOR s IN plan IF s.status == "failed"]

        # ---- 分支一：全部成功 → 总结 ----
        IF NOT failed_steps AND state.current_step_idx >= len(plan):
            RETURN {route_to: "summarizer"}

        # ---- 分支二：有失败 → Reflexion 反思 ----
        failed = failed_steps[0]
        reflection = generate_reflection(failed, state)   # LLM 生成

        # 存入情景记忆（供未来参考）
        memory.store_episode(
            content=reflection.text,
            metadata={task_id: state.trace_id, tool: failed.action,
                      error: failed.error}
        )

        # ---- 选择修复策略 ----
        strategy = decide_strategy(reflection, failed.retry_count)

        SWITCH strategy:
            CASE "retry":
                failed.status = "pending"           # 重置状态
                RETURN {route_to: "executor",
                        current_step_idx: plan.index(failed)}

            CASE "skip":
                failed.status = "cancelled"
                RETURN {route_to: "executor"}

            CASE "replan":
                IF state.replan_count < MAX_REPLAN_COUNT:
                    RETURN {route_to: "planner",
                            replan_count: state.replan_count + 1,
                            failure_context: reflection.text}   # 注入 planner
                ELSE:
                    RETURN {route_to: "summarizer",
                            failure_reason: "超过最大重规划次数"}

            CASE "abort":
                RETURN {route_to: "summarizer",
                        failure_reason: reflection.summary}

    FUNCTION generate_reflection(failed_step, state) -> Reflection:
        RETURN llm.chat(
            prompt=REFLECTION_PROMPT.format(
                step=failed_step.action,
                args=failed_step.arguments,
                error=failed_step.error,
                retry_count=failed_step.retry_count,
                task=state.task
            ),
            response_format=Reflection
            # Reflection: {summary, root_cause, suggested_fix, severity}
        )

    FUNCTION decide_strategy(reflection, retry_count) -> str:
        IF retry_count < MAX_STEP_RETRIES AND
           reflection.severity IN ("transient", "parameter_error"):
            RETURN "retry"
        ELIF reflection.severity == "permanent_tool_error":
            RETURN "skip"
        ELIF reflection.severity == "planning_flaw":
            RETURN "replan"
        ELSE:
            RETURN "abort"
```

### 5.3 升级点

| 升级 | 说明 |
|------|------|
| **Reflexion 记忆** | 每次失败生成反思并存入情景记忆，未来相似任务可避免 |
| **三级反思** | 步骤级（快速修复）→ 任务级（记录经验）→ 全局级（策略调整） |
| **根因分类** | 区分瞬时错误（重试）、参数错误（修复）、工具故障（跳过）、规划缺陷（重规划） |

CLASS Summarizer:
    TEMPLATES = {
        "notify_event":    NOTIFY_SUMMARY_TEMPLATE,
        "greeting":        GREETING_SUMMARY_TEMPLATE,

CLASS MemoryManager:
    # ==================== 工作记忆 ====================
    FUNCTION get_working_context(trace_id) -> dict:
        # 从 LangGraph checkpoint 恢复当前任务上下文
        checkpoint = langgraph_checkpointer.get(trace_id)
        RETURN checkpoint.context

    FUNCTION update_working_summary(trace_id, summary_text):
        # 将长上下文压缩为摘要，替换原始内容
        checkpoint = langgraph_checkpointer.get(trace_id)
        checkpoint.context["summary"] = summary_text
        langgraph_checkpointer.put(trace_id, checkpoint)

    # ==================== 情景记忆 ====================
    FUNCTION store_episode(content, metadata):
        embedding = embedding_model.encode(content)
        chroma_collection("semantic_memory").upsert(
            ids=[uuid()],
            embeddings=[embedding],
            documents=[content],
            metadatas=[metadata]
        )

    FUNCTION recall_episodes(query, top_k=5) -> list[Episode]:
        query_emb = embedding_model.encode(query)
        results = chroma_collection("semantic_memory").query(
            query_embeddings=[query_emb], n_results=top_k
        )
        RETURN [Episode(doc, meta, dist) FOR doc, meta, dist IN results]

    # ==================== 语义记忆 ====================
    FUNCTION recall_facts(user_ids, keys=None) -> dict:
        # MySQL 精确查询
        rows = mysql.query(
            "SELECT * FROM memory_facts WHERE virtual_user_id IN :user_ids"
            + (" AND fact_key IN :keys" IF keys ELSE "")
        )
        RETURN group_by_user(rows)

    FUNCTION write_fact(user_id, key, value, source_task_id):
        # UPSERT：存在则更新，不存在则插入
        mysql.execute("""
            INSERT INTO memory_facts (user_id, fact_key, fact_value, source_task_id)
            VALUES (:user_id, :key, :value, :source)
            ON DUPLICATE KEY UPDATE fact_value=:value, source_task_id=:source
        """)

    # ==================== 程序记忆 ====================
    # 程序记忆不需要显式函数，体现在：
    # - PLAN_TEMPLATES 字典
    # - prompts/*.md 模板文件（git 版本化）
    # - tool_registry 配置

    # ==================== 混合检索（供 Planner 使用） ====================
    FUNCTION hybrid_search(query, top_k=5) -> HybridResult:
        # 向量检索
        vec_results = chroma_collection("knowledge_base").query(...)
        # BM25 检索
        bm25_results = bm25_index.search(query, top_k=top_k*2)
        # RRF 融合
        fused = reciprocal_rank_fusion(vec_results, bm25_results)
        RETURN fused[:top_k]

```pseudocode
CLASS ToolRegistry:
    tools: dict[str, BaseTool] = {}

    FUNCTION register(tool: BaseTool):
        tools[tool.name] = tool

    FUNCTION get(name) -> BaseTool:
        IF name NOT IN tools: RAISE ToolNotFoundError(name)
        RETURN tools[name]

    FUNCTION exists(name) -> bool:
        RETURN name IN tools

    FUNCTION validate_args(name, args) -> bool:
        tool = tools[name]
        try:
            tool.args_schema(**args)    # Pydantic 校验
            RETURN True
        EXCEPT ValidationError:
            RETURN False

    FUNCTION get_descriptions() -> str:
        # 生成给 LLM 的工具目录描述
        RETURN "\n".join([
            f"- {name}: {tool.description}\n  参数: {tool.args_schema.schema()}"
            FOR name, tool IN tools.items()
        ])


CLASS NotificationGateway:
    CHANNELS = {
        "email":    SMTPSender(),
        "wechat":   WeChatWorkWebhook(),
        "lzmx":     MCPBridge("send_lzmx_text_message"),
    }
    RATE_LIMITS = {"email": 60/min, "wechat": 30/min, "lzmx": 30/min}

    FUNCTION dispatch(recipient, channel, content, template_vars) -> SendResult:
        # 速率检查
        IF NOT rate_limiter.allow(channel):
            RETURN SendResult(success=False, error="速率限制")

        # 获取发送器
        sender = CHANNELS.get(channel)
        IF sender IS NULL:
            # 自动降级
            fallback = get_fallback_channel(recipient)
            sender = CHANNELS[fallback]
            channel = fallback

        # 渲染模板
        rendered = render_template(content, template_vars)

        # 发送（带重试）
        FOR attempt IN range(3):
            try:
                result = await sender.send(recipient, rendered)
                log_send_history(recipient, channel, "success")
                RETURN SendResult(success=True, channel=channel)
            EXCEPT SendError AS e:
                IF attempt == 2:
                    log_send_history(recipient, channel, "failed", str(e))
                    RETURN SendResult(success=False, error=str(e))
                await sleep(2 ** attempt)   # 指数退避


CLASS MCPBridge(BaseTool):
    """将远程 MCP 工具包装为本地工具"""

    FUNCTION __init__(mcp_tool_name, mcp_server_url, mcp_token):
        this.mcp_tool_name = mcp_tool_name
        this.mcp_server_url = mcp_server_url
        this.mcp_token = mcp_token

    FUNCTION run(args, ctx) -> ToolResult:
        # 建立 SSE 连接，调用远程工具
        async WITH sse_client(url, token) AS (read_stream, write_stream):
            async WITH ClientSession(read_stream, write_stream) AS session:
                await session.initialize()
                result = await session.call_tool(
                    this.mcp_tool_name,
                    args.model_dump()
                )
                RETURN ToolResult(success=True, data=result.content)
```
