已完成当前开发原型的前后端审核、修复和验证，可作为带明确能力边界的原型仓库上传。此结论不代表生产环境安全审计通过；尚未实现的生产能力列在根目录 README。

## 本次修复

| 范围 | 问题 | 结果 |
| --- | --- | --- |
| 执行分支 | 一个分支依赖失败会跳过同批次所有步骤 | 按步骤判断依赖，无关分支继续执行 |
| 任务结果 | 关键步骤被跳过可能仍报整体成功 | 所有分支结束后统一检查关键失败和关键阻塞 |
| 执行语义 | 关键失败是否终止整个任务存在歧义 | 按用户确认规则：仅阻塞失败分支，独立分支继续 |
| 参数模板 | 列表中的占位符不解析，多占位符文本被误认成单一引用 | 支持嵌套列表和混合文本，保留完整引用的对象类型 |
| 工具契约 | 参数提取只覆盖少量工具，数组/对象被定义为字符串 | Schema 从工具签名生成，调用前做 Pydantic 类型校验 |
| 通知链路 | 用户字典按姓名索引而事件按 ID 索引，内容字典被当列表处理 | 统一用户 ID 索引，通知支持列表或按收件人索引的内容字典 |
| 重试 | 成功后的重试次数丢失，修复会修改原始计划，备用工具可能不存在 | 保留次数，复制步骤，校验备用工具；权限错误不切换通道 |
| 超时 | 配置未实际限制执行 | 工具与执行器限制等待时间，同步工具进入线程池 |
| 规划 | 模型可选择未注册工具，混入错误工具后被静默过滤 | 工具来源统一注册表，错误计划整体拒绝 |
| 意图与上下文 | 主聊天未加载数据库意图，动态参数提取缺原始任务 | 接入启用意图加载，计划保留 original_input，兜底识别返回槽位 |
| 记忆 | 经验存储故障覆盖已成功结果，耗时始终为零 | 可选经验读写降级，记录写入前耗时 |
| 向量查询 | 多字段直接过滤不符合 Chroma 过滤语法 | 使用显式 $and 条件 |
| 配置 | LLM 和 Embedding 的模型名被默认参数/硬编码覆盖 | 实际客户端采用配置模型名 |
| 启动 | 全新克隆时 data 目录不存在，SQLite 初始化失败 | 初始化前创建数据库父目录 |
| API | 空白输入和过长输入没有限制，CORS 过宽 | 参数长度校验，默认本机来源白名单 |
| 前端 | 历史无限增长会超过后端限制，响应体读取超时被误报 | 保留最近 100 条历史，区分超时和非 JSON 响应 |
| 工程 | 测试脚本固定本机绝对路径，没有根目录交付说明 | 使用相对项目路径，补充 README、配置示例、忽略规则与 CI |
