# 审核与验证（0.5.0）

本轮将步骤级持久化、计划版本及基于依赖的局部恢复接入默认聊天和显式 DAG。工具调用前提交尝试及解析后的实际参数，结果完成立即落库；模型路由、检索评估和最终回答也独立保存阶段检查点。原 TaskCheckpoint 预留表保持不变。

78 个 Python 测试通过。新增验证包括：A 失败而 B/C 成功后，增加 B→A，仅补跑 A；修改 A 后使其传递下游失效而保留独立分支；B 完成即启动 A，不等待无关的慢 C；取消保留成功分支；旧代次禁止回写；依赖环、缺失依赖、版本冲突及跨用户恢复拒绝；重复恢复只允许一次领取；配置变化及旧会话轮次阻止恢复；重试和三次搜索预算不会被恢复重置；结果未知的有副作用工具不会自动重放。

真实进程退出测试：第一进程在 B 成功落库后、A 执行中直接 os._exit；新进程加载同一数据库，识别未知尝试、增加执行代次，复用 B 并完成 A。另有取消竞争测试，验证成功提交后收到取消不会覆盖已确认结果。默认聊天恢复测试验证路由/搜索不重复执行，仅重做失败评估及后续回答。

12 个前端测试通过，vue-tsc 和生产构建通过。检查点面板展示计划版本、执行代次、步骤状态及尝试，支持图 JSON 修订与恢复；恢复请求使用 expected_generation，修订使用 expected_version。原有登录、取消、限流、模型配置和来源安全测试保留。

Chrome 隔离后端验收通过：真实 HTTP 模型 SDK、搜索适配器、三轮检索、检查点查看、修改依赖图、从界面恢复、验证 A 两次尝试而 B/C 各一次，以及历史、账号隔离和手机布局。测试使用本地提供方，无真实模型费用，未出现 JS 异常。

文档、中英文 README 和 OpenAPI 已同步，详见 [检查点与恢复](checkpoints.md)。当前仍为单 worker、手动恢复，不是分布式自动接管；旧任务不能追溯恢复，不完整的模型生成会重新请求，外部副作用未知不自动重放，数据库不可写时仍无法保证结果落盘。本轮改动未推送 GitHub。
