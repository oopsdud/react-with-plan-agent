# 意图识别与规划模块 · 技术选型与落地方案

> **架构定位**：LangGraph ReAct-with-Plan 混合架构的前置模块
> **核心流程**：语义路由 → Query 替换 → 意图分流 → 骨架规划（含 Few-shot）→ 动态执行
> **设计原则**：意图识别只做"路由和参数提取"，不做"完整计划生成"

---

## 1. 架构流程

```
用户输入
    │
    ▼
┌─────────────────────────────────────────┐
│  1. 语义路由（BGE-M3，~5ms）              │
│  └─ 输出：IntentDecision                  │
│      {intent_id, complexity, confidence, │
│       is_multi_intent}                    │
└────────────────────┬────────────────────┘
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
    【多意图】                【单意图】
    is_multi=true             is_multi=false
         │                       │
         ▼                       ▼
┌──────────────────┐    ┌──────────────────┐
│ 2a. 子图并行策略  │    │ 2b. Query 替换    │
│    (仅此时触发)   │    │    (~200ms)      │
│                  │    │                  │
│ 拆分子任务        │    │ 指代消解          │
│ 检测依赖关系      │    │ 时间标准化        │
│ 并行/串行执行     │    │ 实体链接          │
└────────┬─────────┘    └────────┬─────────┘
         │                       │
         └───────────┬───────────┘
                     ▼
┌─────────────────────────────────────────┐
│  3. 双通道分流                             │
│                                          │
│  【Simple 通道】complexity = simple       │
│  ├─ 正则提取参数                         │
│  ├─ 失败→LLM 提参（保持单步）             │
│  └─ 直接调用工具（零 LLM 规划）           │
│                                          │
│  【Complex 通道】complexity = complex     │
│  ├─ 检索相似任务骨架（Few-shot）          │
│  ├─ LLM 生成计划骨架（仅步骤序列，无参数） │
│  └─ 输出到 ReAct Executor                │
│                                          │
│  【Fallback】无匹配或置信度 < 0.6         │
│  └─ LLM 兜底识别 → 仍失败则人工澄清       │
└─────────────────────────────────────────┘
```

## 2. 核心概念定义

### 2.1 extracted_slots（提取槽位）

Query 替换后提取的**结构化实体信息**，用于 ReAct 执行时动态填充参数：

```python
extracted_slots = {
    "person": ["张三", "李四"],           # 人名列表
    "datetime": "2025-09-30T15:00:00",    # 标准化时间
    "file_id": "f-123",                   # 实体链接后的文件ID
    "meeting_topic": "项目评审",          # 主题
    "location": "会议室A"                 # 地点
}
```

**作用**：ReAct 执行 Step 时，LLM 看到这些预提取的槽位，直接填入工具参数，不用从原始文本重新理解。

### 2.2 双通道分流依据

分流依据是**意图元数据中的 complexity 字段**（存储在 SQLite）：

| 分流条件 | 通道 | 处理方式 | 典型场景 |
|---------|------|---------|---------|
| `complexity = 'simple'` | **Simple** | 正则提取参数 → 直接调工具 | 查天气、设闹钟、查股价 |
| `complexity = 'complex'` | **Complex** | 检索 Few-shot 骨架 → LLM 生成骨架 → ReAct 执行 | 通知开会、批量导入、多步骤任务 |
| 语义相似度 < 0.6 | **Fallback** | LLM 兜底识别或追问澄清 | 模糊指令、闲聊、超出能力范围 |

**Simple vs Complex 本质区别**：

| 维度 | Simple | Complex |
|------|--------|---------|
| **工具数量** | 1 个 | 多个（2-5个） |
| **参数来源** | 当前输入明确 | 依赖上一步执行结果 |
| **规划需求** | 不需要 | 需要骨架（步骤序列） |
| **LLM 调用** | 0 次（正则提取） | 1 次（骨架生成）+ N 次（ReAct 执行） |

## 3. 多意图处理：子图并行策略

### 3.1 触发条件

**仅在语义路由检测到多意图时触发**：

```python
# 触发条件 1：连接词检测
"通知张三开会**并**把纪要存到知识库"  # 并列连词
"查天气**然后**提醒我带伞"            # 时序连词
"**先**导入文档，**再**通知项目组"     # 显式顺序

# 触发条件 2：语义路由返回多个意图且分数接近
intent_scores = {
    "notify_event": 0.82,
    "ingest_document": 0.79   # 差距 <0.15，判定为组合
}
```

### 3.2 执行架构：Split → Detect → Execute

```
用户输入："通知张三开会并把纪要存到知识库"
    │
    ▼
┌─────────────────────────────────────────┐
│ 1. 意图拆分（Multi-Intent Split）        │
│  └─ 基于连接词/语义相似度拆分             │
│  └─ 子任务1：通知张三开会 (notify_event)  │
│  └─ 子任务2：存纪要到知识库 (ingest)      │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│ 2. 依赖关系判定（Dependency Detection）   │
│                                          │
│  【并行】无依赖：同时执行                  │
│  例："查天气和查股票" → asyncio.gather   │
│                                          │
│  【串行】有依赖：先执行前置子图            │
│  例："开会并存纪要" → 先meeting_id       │
│                       再存纪要            │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│ 3. 子图执行（SubGraph Execution）         │
│                                          │
│  每个子图独立运行 ReAct-with-Plan：       │
│  ├─ 独立 skeleton                        │
│  ├─ 独立 executor                        │
│  ├─ 独立 checkpoint（thread_id/child_N） │
│  └─ 独立状态隔离                          │
│                                          │
│  子图间通信：                             │
│  ├─ 串行：通过 context 传递结果           │
│  └─ 并行：父图汇总后统一处理              │
└─────────────────────────────────────────┘
```

### 3.3 状态隔离设计

| 维度 | 单意图 | 多意图子图 |
|------|--------|-----------|
| **AgentState** | 单一全局状态 | 子图独立状态 + 父状态汇总 |
| **Checkpointer** | 单 thread_id | 父 thread_id + 子 thread_id（如 `parent/child_1`） |
| **Memory 写入** | 直接写 | 子图完成后统一写（避免部分失败污染） |
| **审批** | 单次审批 | 子图合并后统一审批（推荐） |
| **失败隔离** | 整体失败 | 子图失败不影响其他子图（部分成功） |

### 3.4 伪代码实现

```python
async def handle_user_input(user_input):
    # 1. 语义路由
    route_result = semantic_route(user_input)
    
    # 2. 关键判断：是否多意图
    if route_result.is_multi_intent:
        return await handle_multi_intent_subgraphs(route_result)
    else:
        return await handle_single_intent(route_result)

async def handle_multi_intent_subgraphs(route_result):
    # 拆分
    sub_tasks = split_multi_intent(route_result.user_input)
    
    # 检测依赖
    dependencies = detect_dependencies(sub_tasks)
    
    if dependencies.has_serial_dependency():
        # 串行执行：先执行子图1，结果注入子图2
        result1 = await run_subgraph(sub_tasks[0])
        result2 = await run_subgraph(sub_tasks[1], context=result1)
        return merge_results([result1, result2])
    else:
        # 真并行：同时启动多个子图
        tasks = [run_subgraph(t) for t in sub_tasks]
        results = await asyncio.gather(*tasks, return_exceptions=True)
        return merge_results(results, partial_success=True)

async def run_subgraph(sub_task, parent_context=None):
    # 独立 ReAct 执行
    # 有独立的 skeleton、executor、checkpoint
    rewritten = query_rewrite(sub_task, parent_context)
    skeleton = plan_skeleton(rewritten, few_shot_retrieval=True)
    return await react_execute(skeleton, context=parent_context)
```

## 4. 技术选型

### 4.1 语义路由模型

| 方案 | 模型 | 部署 | 延迟 | 决策 |
|------|------|------|------|------|
| **主选** | **BGE-M3** | 本地 Docker (TEI) | 5-10ms | ✅ 采用 |
| 备选 | bge-base-zh | 本地 CPU | 3-5ms | 资源受限时 |

### 4.2 Query 替换实现

| 功能 | 方案 | 说明 |
|------|------|------|
| **指代消解** | LLM (轻量) | 输入：当前文本 + 最近3轮历史，输出：消解后文本 |
| **时间标准化** | 规则引擎 | `dateparser` 库 + 中文日期解析 |
| **实体链接** | 混合 | 最近文件/用户查询 + LLM 兜底 |

**推荐库**：
```python
# 时间解析
import dateparser
dateparser.parse("明天下午三点", settings={'RELATIVE_BASE': datetime.now()})

# 指代消解（简化版）
def resolve_references(text, history):
    if "他" in text and history.last_person:
        return text.replace("他", history.last_person)
```

### 4.3 Few-shot 骨架检索

**存储**：ChromaDB `semantic_memory` 集合

**检索逻辑**：
```python
# 1. 将 Query 替换后的文本向量化
query_emb = bge_m3.encode(rewritten_text)

# 2. 检索相似任务（只取骨架，不取参数）
results = chroma_collection.query(
    query_embeddings=[query_emb],
    n_results=3,
    where={"type": "successful_skeleton"}
)

# 3. 提取骨架序列（Strip 具体参数）
few_shot_skeletons = [
    {"input": r.metadata["original_input"], 
     "skeleton": r.metadata["skeleton_steps"]}  # 仅步骤名
    for r in results
]
```

## 6. Fallback 与降级策略

### 6.1 Simple 通道正则失败

**不直接转 Complex 规划**，而是 **"Simple 意图 + LLM 参数提取"** 的混合模式：

```python
def handle_simple_intent(intent_entry, user_input):
    # 尝试正则提取
    params = extract_by_regex(user_input, intent_entry.param_patterns)
    
    if params is valid:
        return execute_tool(intent_entry.tool_name, params)
    
    # 失败：降级为 LLM 参数提取，但保持 Simple 骨架（单步）
    else:
        llm_params = llm.extract_params(
            tool_schema=intent_entry.tool_schema,
            user_input=user_input,
            few_shot=intent_entry.param_examples
        )
        
        if validate(llm_params, intent_entry.required_params):
            return execute_tool(intent_entry.tool_name, llm_params)
        else:
            return ask_for_missing_params(intent_entry.required_params - llm_params.keys())
```

### 6.2 语义路由失败（三级 Fallback）

```python
def semantic_route_with_fallback(user_input):
    # Level 1: BGE-M3 语义检索
    intent, score = chroma_search(user_input)
    
    if score > 0.85:
        return intent
    
    elif score > 0.6:
        # Level 2: 模糊匹配，转 LLM 确认
        llm_result = llm.classify(
            user_input=user_input,
            candidate_intents=[intent],  # 只给候选
            allow_reject=True
        )
        if llm_result.confidence > 0.8:
            return llm_result.intent
        else:
            return fallback_to_clarification(user_input)
    
    else:
        # Level 3: 完全无匹配，LLM 开放式识别
        llm_result = llm.classify(
            user_input=user_input,
            candidate_intents=all_active_intents,
            allow_reject=True
        )
        if llm_result.confidence > 0.7:
            return llm_result.intent
        else:
            return handle_general_conversation(user_input)  # 最终 Fallback
```

### 7.1 Prometheus 指标

| 指标名 | 类型 | 说明 | 告警阈值 |

## 9. 迭代路径

| 阶段 | 动作 | 产出 |
|------|------|------|
| **Week 1** | 录入 20 个意图 + 10 条成功骨架 + 多意图拆分规则 | 可用系统 |
| **Week 2** | 监控 Query 替换错误案例（消解错误、时间解析错误） | 规则优化清单 |
| **Week 3** | 优化 Few-shot 检索（调整相似度阈值、增加骨架多样性） | 骨架命中率 +15% |
| **Week 4** | **闭环学习**：成功执行后自动提取骨架入库；多意图案例标注 | 自学习系统 |

**闭环学习伪代码**：
```python
def on_task_success(trace_id, original_input, executed_steps, is_multi=False):
    if is_multi:
        # 多意图：提取每个子图的骨架
        for sub_task in executed_steps.sub_tasks:
            skeleton = [step.action for step in sub_task if step.status == "succeeded"]
            save_skeleton(sub_task.original_input, skeleton)
    else:
        # 单意图：提取骨架
        skeleton = [step.action for step in executed_steps if step.status == "succeeded"]
        save_skeleton(original_input, skeleton)
    
    update_intent_stats(intent_id, success=True)
```
